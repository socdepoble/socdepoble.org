## 1. FORTIFICACIÓ I BOMBARDEIG (Defectes P0 i Trencaments)

### 1.1. Defecte P0: S2 INSTANCIA-UNICA (El Singleton Disfressat)
*   **Ruta:** `tooling/gates/tractor-sollutia.mjs`
*   **Evidència:** La llei `S2 INSTANCIA-UNICA` documenta que el `connectedCallback` del Web Component "desmunta les altres instàncies connectades".
*   **Bombardeig:** Si l'arquitectura de Sollutia (l'hoste) intenta renderitzar una llista de components Pedra Seca, o si el seu editor mostra la previsualització al costat de l'edició (dos instàncies a la mateixa pàgina), **la primera instància morirà**. Un Custom Element que no admet múltiples instàncies és un Singleton que destruirà el DOM de l'hoste en producció.

### 1.2. Defecte P0: Col·lisió de Dominis OAuth (Frontera Auth)
*   **Ruta:** `tooling/gates/tractor-frontera-auth.mjs`
*   **Evidència:** Discrepància crítica entre la configuració i la documentació.
    *   `src/data/oauthRelay.js` defineix: `RELAY_PER_DEFECTE = https://auth.socdepoble.org/callback`
    *   `public/auth/callback.html` documenta el desplegament a: `...socdepoble.cat/callback`
*   **Bombardeig:** L'OAuth fallarà en producció amb un error `redirect_uri_mismatch` (HTTP 400) del proveïdor d'identitat. La costura d'autenticació està fracturada.

### 1.3. Defecte P0: Portes de Seguretat "Tombstone" (SDP-LOCK)
*   **Ruta:** `scripts/audit-performance.sh`
*   **Evidència:** `echo "SDP-LOCK: auditoria a11y automàtica retirada fins integrar axe com a dependència fixada..."`
*   **Bombardeig:** L'auditoria d'accessibilitat (a11y) i rendiment està literalment **apagada i bloquejada**. El sistema de CI/CD està volant a cegues; no hi ha cap gate automàtic que vigil·li l'accessibilitat ni el rendiment en l'actualitat.

## 2. CERCA DE CONTRADICCIONS (Lògica i Arquitectura)

### 2.1. La Porta SEO és un Stub (Teatre de Seguretat)
*   **Ruta:** `tooling/wiki/seo_auditor.mjs`
*   **Evidència:**
    ```javascript
    export async function auditSEO() {
      console.log(`[SEO] Iniciant auditoria d'estructura SEO...`);
      // Stub
      console.log(`✅ [SEO] Compleix l'estàndard de Pedra Seca (Stub).`);
    }
    ```
*   **Contradicció:** La missió exigeix "deixar-lo impenetrable i perfecte", però la porta de seguretat que ho valida fa trampes i retorna `✅` incondicionalment. El sistema creu que el SEO és perfecte quan en realitat **no s'està avaluant absolutament res**.

### 2.2. Fantasmes CSS i Tokens Orfes (Llei S1)
*   **Ruta:** `tooling/gates/tractor-sollutia.mjs` (Llei S1 VAR-ORFE-AMFITRIO)
*   **Evidència:** L'hoste (`index.html`, `blank.php`) usa variables com `--sdp-fons-app` i `--sdp-bg` que **no existeixen** enlloc. El fallback cau a `#f4eee6`, que no és cap token vàlid de Pedra Seca (el token càlid real és `#fff4ef`).
*   **Contradicció:** Es ven un sistema de disseny estricte i aïllat, però la costura amb l'hoste està plena de colors hardcoded aliens al sistema de disseny, violant l'encapsulament.

### 2.3. El Mort que Camina (Offline-First vs Online-First)
*   **Ruta:** `_wiki_de_poble/10_actes/...` vs `MOTOR_OFFLINE`
*   **Evidència:** Les actes recents declaren "la mort de l'arquitectura Offline-First" i el pas estricte a "Online-First (Realtime via Supabase)". No obstant això, la skill `[[MOTOR_OFFLINE]]` continua citada, ancorada i viva a `02_ACTUAR_Maquina_Tecnica/skills/MOTOR_OFFLINE.md`.
*   **Contradicció:** El cervell (Wiki) manté òrgans vitals d'una arquitectura que el Cos (Actes) ha declarat morta i arxivada.

## 3. AUDITORIA D'ENXUFABILITAT (Fricció Sollutia)

### 3.1. La Frontera de les Escriptures (Frontissa)
*   **Ruta:** `src/data/frontissa/sollutia/recursos.js`
*   **Evidència:**
    ```javascript
    function escriu(nomRecurs) {
      // ...
      throw new ErrorFrontera('escriptures encara no implementades');
    }
    ```
*   **Impacte:** La UI és estrictament de lectura (`F2 LECTURA`). Qualsevol intent de l'usuari de crear, actualitzar o esborrar dades (POST/PUT/DELETE) des del mòdul Pedra Seca cap a Sollutia resultarà en un **crash immediat** de l'aplicació (`ErrorFrontera`). L'enxufabilitat actual és unidireccional i incompleta.

### 3.2. IIFE, Shadow DOM i l'Aïllament de l'Estat
*   **Ruta:** `_wiki_de_poble/02_saber/estandard_integracio_react.md`
*   **Evidència:** "Pedra Seca porta el seu propi React i el seu Enrutador Natiu encapsulats dins del Shadow DOM. Sollutia NO necessita instal·lar React ni React Router."
*   **Impacte:** Un Web Component amb Shadow DOM i React propi aïllat no pot compartir l'estat global (Context/Redux) ni els esdeveniments de ruteig de la SPA de Sollutia de forma nativa. La comunicació ha de ser estrictament via `postMessage` o Custom Events. Si Sollutia assumeix que pot passar un `Context.Provider` per sobre del Web Component, la integració fallarà silenciosament.
