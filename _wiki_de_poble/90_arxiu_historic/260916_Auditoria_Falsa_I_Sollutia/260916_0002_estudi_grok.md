### 2. Arquitectura inversa (desmuntatge → forats → reconstrucció)

**Nucli observat**  
- Front: Vite + Preact (`vite.config.js`, `src/main.jsx`, `src/app/App.jsx`).  
- Backend: Supabase (migrations a `supabase/migrations/`, clients a `src/data/supabase/`).  
- Capes de dades: `src/data/frontissa/` (traductor, DTO, esquema, client local IDB + Sollutia).  
- Governança: `.agents/`, `tooling/gates/tractor-*.mjs`, `tooling/wiki/`, deute segellat a `.agents/deute/`.  
- Auth: OAuth relay (`src/data/oauthRelay.js` + `public/auth/callback.html`).

**Flux de dades reconstruit**  
1. Entrada usuari → `App.jsx` / contexts (`SessionContext`, `RouterContext`, `UIContext`).  
2. Contingut → `frontissa/traductor.js` + `dto.js` + `esquema.js`.  
3. Persistència local → `frontissa/local/idb.js`.  
4. Remot → `frontissa/sollutia/client.js` + `recursos.js` **o** clients Supabase directes.  
5. Auth → `oauthRelay.js` → `callback.html` (postMessage + ORIGENS_PERMESOS).

**Punts de ruptura detectats (bombardeig)**  
- **Doble font de veritat backend**: Supabase (migrations + clients) i Sollutia (`frontissa/sollutia/`) coexistixen sense un únic contracte de fallada. Si Sollutia no respon, el camí de fallback no està declarat de forma mecànica en el cos llegible.  
- **Auth asimètrica**: `oauthRelay.js` defineix `RELAY_PER_DEFECTE`; `callback.html` documenta orígens. El tractor `tractor-frontera-auth.mjs` existeix precisament perquè aquests dos costats poden divergir (lleis A1–A6).  
- **Esquemes frontmatter duals**: `tooling/wiki/schema.json` (v2) i `esquema_frontmatter.json` (v1). El tractor `tractor-esquemes.mjs` comprova divergències (E1–E4); si no coincideixen, cap document pot satisfer les dues lleis alhora.  
- **Skills / RAG**: `tractor-cognitiu.mjs` detecta skills inabastables (P5), frontmatter fantasma (P1), disparadors destruïts (P8).  
- **Nomenclatura**: `tractor-nomenclatura.mjs` mesura rutes mortes citades al codi (N2) — històricament 15/19 rutes `_wiki_de_poble/...` apuntaven a carpetes inexistents.

**Reconstrucció mínima viable per a producció**  
1. Unificar font de veritat de backend a un sol adapter (`frontissa`) amb contracte de timeout + circuit-breaker.  
2. Fer passar `tractor-frontera-auth.mjs`, `tractor-esquemes.mjs`, `tractor-frontmatter.mjs --estricte` i `tractor-nomenclatura.mjs` a zero deute abans de desplegar.  
3. Eliminar qualsevol camí que escriga al disc sense passar per la Canonada (`tractor-cognitiu.mjs` P4).

### 4. Auditoria d’enxufabilitat Sollutia (màxim rigor)

**Components presents al manifest**  
- `src/data/frontissa/sollutia/client.js`  
- `src/data/frontissa/sollutia/recursos.js`  
- `src/data/frontissa/traductor.js`, `dto.js`, `esquema.js`, `local/idb.js`  
- `tooling/gates/tractor-sollutia.mjs` (referenciat)  
- `tooling/mocks/sollutiaBackend.js`  
- Auth: `oauthRelay.js` + `public/auth/callback.html`

**Contracte observat**  
- Frontissa actua com a adaptador: DTO + traductor + client local + client Sollutia.  
- No hi ha al cos llegible un test d’integració end-to-end que demostri que un flux complet (auth → lectura → escriptura → realtime) passa sense invenció.  
- El mock existeix (`tooling/mocks/sollutiaBackend.js`), però el contracte de fallada (timeout, 4xx/5xx, circuit) no està exposat de forma única i verificable al text proporcionat.

**Forats d’enxufabilitat**  
1. **Orígens permesos**: si la llista a `callback.html` no conté els hosts reals de Sollutia (llei A4), l’entrada amb Google des de WordPress de client rep “Origen no reconegut”.  
2. **Relay URL**: divergència JS/HTML → postMessage rebutjat en silenci.  
3. **Camí cru**: `sdp_path` sense validació rigorosa (llei A5) pot trencar el fragment.  
4. **Sense circuit-breaker visible**: si Sollutia cau, el front pot quedar penjant o caure a un estat no declarat.  
5. **Doble persistència**: IDB local + remoto sense política clara de reconciliació al cos llegible.

**Requisits mínims per a “enxufabilitat perfecta” hui**  
- `tractor-frontera-auth.mjs` → 0 infraccions.  
- Un únic `RELAY_PER_DEFECTE` derivat i verificat.  
- Test de smoke (no inventat) que executi auth → recursos → escriptura i falli tancat si el backend no respon.  
- Documentació de contracte (timeout, retries, error codes) dins de `frontissa/`.
