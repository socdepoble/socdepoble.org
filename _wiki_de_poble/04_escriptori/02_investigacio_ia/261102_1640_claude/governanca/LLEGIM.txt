1. Què canvia a tooling/vite/consola-iaia.mjs (resum del diff)
--------------------------------------------------------------

  · local(req) es queda igual de significat (GET + IP local) però la
    comprovació d'IP passa a delMateixOrdinador(req) (IPS_LOCALS), i naix
    localPost(req) = POST + la mateixa comprovació d'IP.
  · Àrbitre T1a-ARB-01 (CSRF, P1) · naixen origenLocal(req) i ambCosJson(req):

    POST ha de portar Origin = http(s)://{localhost|127.0.0.1|[::1]}[:port]
    amb la mateixa autoritat que la capçalera Host, Sec-Fetch-Site absent o
    'same-origin', i Content-Type que comence per application/json.
  · Bloc nou «IDEA-60 · El corredor Jarvis», darrere de servix():

Per què UNA sola ruta registrada per a dos URL: connect accepta un prefix
que acaba en «/», en «.» o al final de la URL, així que
/__iaia/botigues/publica-tot.json també cau dins de la capa de
/__iaia/botigues/publica-tot, i connect lleva el prefix de req.url (queda
'.json', '' o '/'). gestorJarvis mira el sufix i el mètode. Una prova que
crida el gestor a pèl (sense connect) pot passar la URL sencera: el gestor
lleva el prefix si hi és.

Guardes del gestor (en este ordre):
  GET  <ruta>.json  des de fora                  → 403 'Forbidden' (text, com les quatre fonts)
  GET  <ruta>.json  local, cap corredor arrancat → 404 { schema, codi: 'cap', error }
  GET  <ruta>.json  local                        → 200 { schema, estat, passos, iniciat }
  POST <ruta>       des de fora                  → 403 'Forbidden'
  GET/PUT/PATCH/DELETE <ruta> (sense .json)      → 403 'Forbidden' (només POST arranca)
  POST <ruta> local sense Origin, o amb un Origin que no és el d'este
       servidor (http://evil.example, http://localhost:8080 quan Host és
       localhost:3340), o amb Sec-Fetch-Site ≠ 'same-origin'
                                                 → 403 'Forbidden' (CSRF; cap procés arrancat)
  POST <ruta> local del mateix origen sense Content-Type application/json
       (text/plain d'un <form> o d'un fetch no-cors)
                                                 → 415 { schema, codi: 'cos', error } (cap procés arrancat)
  POST <ruta> local, cos > 4096 bytes            → 413 { schema, codi: 'mida', error }
  POST <ruta> local, cos que no és JSON o no passa validaPeticioJarvis
                                                 → 400 { schema, codi: 'cos', error }
  POST <ruta> local, ja n'hi ha un 'en_curs'     → 409 { schema, codi: 'ocupat', error }
  POST <ruta> local, execFile falla en arrancar  → 500 { schema, codi: 'arrancada', error }
  POST <ruta> local, bo                          → 202 { schema, estat: 'en_curs', passos }
Cap error porta camins ni text del sistema: ERROR_JARVIS són textos fixos.
El connector és apply 'serve': el build no coneix la ruta (com les altres).


2. Contracte JSON (sdp.jarvis.publica.v1)
-----------------------------------------
2.1 Petició (POST, Content-Type: application/json, ≤ 4096 bytes)
  {
    "schema": "sdp.jarvis.publica.v1",
    "notes":  "<text, 1..500 caràcters després de trim; salts de línia \n; cap caràcter de control fora de tab i salt>",
    "canals": ["web", "wordpress", "android", "ios"],   // subconjunt; [] vol dir tots; un id desconegut invalida la petició
    "sec":    false                                      // booleà obligatori; true = assaig (el corredor no puja res)
  }
  La Consola (jarvis.js · peticioPublicaTot) envia sempre la llista
  explícita dels canals que es veuen (els quatre a la web; tres dins de
  l'app nativa, on el botó va desactivat de totes maneres).

2.2 Resposta d'arrencada (202)
  {
    "schema": "sdp.jarvis.publica.v1",
    "estat":  "en_curs",
    "passos": [
      { "id": "web",       "canal": "web",       "titol": "1/4 Web al dia",                 "estat": "pendent" },
      { "id": "wordpress", "canal": "wordpress", "titol": "2/4 WordPress al dia",           "estat": "pendent" },
      { "id": "android",   "canal": "android",   "titol": "3/4 Google Play i APK enviats",  "estat": "pendent" },
      { "id": "ios",       "canal": "ios",       "titol": "4/4 Apple enviat",               "estat": "pendent" }
    ]
  }
  Amb un subconjunt de canals la numeració és sobre el seu total («1/2 …»).
  Els títols són els mateixos de la Consola (jarvis.js · TITOL_PAS).

2.3 Progrés (GET <ruta>.json, 200)
  {
    "schema":  "sdp.jarvis.publica.v1",
    "estat":   "en_curs" | "fet" | "error",
    "passos":  [ { "id", "canal", "titol", "estat": "pendent"|"en_curs"|"fet"|"error", "detall"?: "<≤ 300 caràcters>" } ],
    "iniciat": "<ISO 8601>"
  }
  La Consola (jarvis.js · llegixProgres) rebutja qualsevol forma que no siga
  esta (schema, estat, passos amb id únic, canal del conjunt, titol no buit
  ≤ 120, estat del vocabulari, detall cadena ≤ 300) i ho pinta com a
  «contacte perdut». Camps de més (iniciat) s'ignoren.
  La Consola demana el progrés cada 2 s fins a 'fet' o 'error', com a molt
  10 minuts (després diu que el corredor porta massa temps). El servidor
  mata el procés als 30 minuts (TEMPS_MAXIM_CORREDOR).

2.4 Com es tanca el progrés (tancaJarvis)
  · 'fet' només si el codi d'eixida és 0 I tots els passos han dit 'fet'.
  · Un pas que es queda 'en_curs' quan el procés acaba passa a 'error'.
  · Qualsevol altra cosa (codi ≠ 0, un pas 'error', un pas 'pendent' que
    ningú ha reportat) és 'error'. Honest: res no es dona per fet si el
    corredor no ho ha dit.


3. Protocol de línies del corredor (scripts/botigues/publica-tot.mjs · carril MarIA)
------------------------------------------------------------------------------------
Ordre amb què el middleware l'arranca (execFile, mai shell, cwd = arrel):
  node scripts/botigues/publica-tot.mjs --notes <notes> --canals web,wordpress,android,ios [--sec]
  · --notes      un sol argument (pot portar espais i salts de línia: viatja
                 com a argv, no per cap intèrpret).
  · --canals     llista separada per comes, en l'ordre de publicació.
  · --sec        assaig: fa totes les comprovacions i no puja res.
  · L'entorn és el del servidor de desenvolupament (process.env tal qual),
    com si s'executara des del terminal: les claus de scripts/botigues/
    entorn.mjs es lligen igual que a puja-android.mjs i puja-ios.mjs. El
    middleware no llig cap valor de l'entorn.

Eixida que el middleware entén (stdout, una línia JSON per esdeveniment):
  {"pas":"web","estat":"en_curs"}
  {"pas":"web","estat":"fet","text":"dist/ al dia (1.0.0)"}
  {"pas":"wordpress","estat":"en_curs"}
  {"pas":"wordpress","estat":"error","text":"empaqueta.mjs ha tornat 1"}
  · pas    l'id del pas = l'id del canal (web | wordpress | android | ios).
  · estat  pendent | en_curs | fet | error.
  · text   opcional, ≤ 300 caràcters (es retalla), SENSE camins absoluts ni
           secrets: el middleware emmascara /Users/…, /home/…, /private/…,
           /var/…, /tmp/…, /etc/…, /opt/… i /Volumes/… amb «<camí>», però el
           corredor no hi ha de confiar. La Consola el pinta dins de
           <Privat> (el mode privacitat l'amaga).
  · Una línia que no és JSON, o amb un pas o estat desconegut, s'ignora:
    els registres humans van a stderr, no a stdout. Una línia de més de
    4096 bytes es descarta.
  · Cada canal demanat ha d'acabar amb una línia 'fet' o 'error': un pas
    sense línia final deixa el progrés en 'error' encara que el procés ixca
    amb 0 (vegeu 2.4).
  · Codi d'eixida: 0 si tots els canals han acabat bé; qualsevol altre, error.
  · La mateixa ordre executada a mà al terminal és el camí de reserva que
    la Consola mostra quan el servidor no porta el corredor (ordreTerminal):
    el script ha de funcionar igual amb stdout a un terminal.

Què ha de fer per canal (per a fixar el contracte, no la implementació):
  web        → build web (vite.config.js) i el que corresponga per a
               desplegar socdepoble.org; avui no hi ha script de
               desplegament al repositori (empaquetats.js · NOTA_ORDRE.pwa):
               si no n'hi ha, el pas ha de dir 'error' amb text, no 'fet'.
  wordpress  → SDP_RELEASE=1 SDP_VERSIO=<v> npm run build:wp i build:wp:directori,
               node wordpress-plugin/eines/empaqueta.mjs …; la pujada a
               WordPress.org (SVN) i a la release de GitHub si l'entorn porta
               les credencials; si no, 'error' amb text.
  android    → node scripts/botigues/puja-android.mjs --versio <v> --build <b> --confirma=<v>+<b>
               (el «sí» del Mestre el dona el POST: les notes són el relleu).
  ios        → node scripts/botigues/puja-ios.mjs --versio <v> --build <b> --confirma=<v>+<b>.
  Les versions i builds ixen de les mateixes fonts que recullEmpaquetats
  (build.gradle, project.pbxproj, package.json, la capçalera del connector),
  amb les regles de scripts/botigues/entorn.mjs. Les notes van a les notes de
  versió de cada botiga (Play Console, App Store Connect, el readme.txt del
  connector) quan el script de cada canal ho admeta.
